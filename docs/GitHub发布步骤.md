# GitHub 发布步骤

## 先检查文件

已整理的“GitHub发布资料”包含 README、图文介绍、项目简介、配图和当前版本的主要源码。配图只包含演示任务。

不要直接把整个工作文件夹上传。以下文件请留在本地：

- `data.json` 及其他数据备份。
- 原软件“参考”文件夹及其 EXE。
- 调试日志、个人任务截图、运行缓存。
- 未核实来源或许可的其他第三方文件。

`.gitignore` 能帮助 Git 排除文件，但通过网页手动上传时仍需自行检查。已经提交过的文件也不会因添加忽略规则而自动从历史中移除。

## 创建仓库

1. 在 GitHub 新建仓库，名称可用 `To-dolist`。
2. 选择 Public 前，确认愿意公开的源码、素材及其授权范围。
3. 把“GitHub发布资料”中的内容上传到仓库根目录，确保 `README.md` 位于最外层。
4. 将 [项目简介](项目简介.md) 中的 About 文案复制到仓库简介。

文档里已经用“本仓库 Issues”作为联系渠道；你也可以自行添加愿意公开的邮箱。文档没有擅自填入个人联系方式。

## 发布 EXE

1. 在仓库的 Releases 页面创建发布版本。
2. 标签可自行填写，例如 `v1.0.0`；版本号由你决定。
3. 上传 `便携单文件版/To-dolist.exe` 作为附件，不上传真实数据文件。
4. 发布说明可以从 [软件介绍](软件介绍.md) 中摘取。

EXE 体积较大，建议放在 Releases，避免每次更新都提交到 Git 源码历史。

## 源码试运行

在“GitHub发布资料”对应的仓库目录中安装 Node.js 后运行：

```sh
npm install
npm start
```

Electron 版本沿用本程序已使用的 31.7.7。公开资料包只整理了主要源码与文档，不包含 Electron 的全部运行组件，也不提供跨平台兼容保证。

## 关于许可证和声明

目前不为整个项目擅自添加 MIT、GPL 等统一授权；源码包的 `license` 标注为 `UNLICENSED`，表示尚未授予项目整体的开放许可，不等于第三方组件没有自己的许可证。

发布前请核实原始代码、参考素材与图标的来源和授权，保留相应说明。README 中的“如有侵权联系删库”是联系与处理态度，不能代替应有的许可。原工作目录内的 `LICENSE` 是 Electron 组件的许可文本，不能直接当作整个 To-dolist 项目的许可证。
